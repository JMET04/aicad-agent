# aicad-agent 详细功能说明

## 1. 设计原则

`aicad-agent` 不是让模型自由拼接 CAD 命令，而是把绘图过程拆成可审计、可失败、可复现的工程流水线：

1. 先理解并冻结用户的整体要求；
2. 再选择明确的结构族与参数实例；
3. 按创建顺序生成实体，并说明每条边的用途、依赖和数学关系；
4. 用独立验证器证明整体语义、几何秩、拓扑和功能合同；
5. 只有全部硬门禁通过后，才构建候选文件；
6. 新发现的错误必须沉淀成永久规则与红色回归。

它重点阻断“局部线段正确、整体产品荒谬”“报告数字正确、实际实例不同”“为了原点协议扭曲功能轮廓”等低级错误。

## 2. 第一关：整体需求一致性

### 2.1 需求契约

`drawing_requirement_contract.schema.json` 将输入区分为用户明确要求、具有尺寸权威的设计数据、结构标准、CAD 参考、只能提供拓扑或外观语义的图片、偏好和推断假设。

契约声明：

- 产品类型、用途和单位；
- 结构族、标准、上部闭合和下部闭合；
- 关键尺寸及其权威来源；
- 必需、允许和禁止的主要功能；
- 输出清单与安全锁；
- 输入权威顺序、假设和冲突解决结果。

### 2.2 实际值强绑定

每条硬要求必须拥有 ASCII requirement ID、typed expected relation、observed 值、至少一条可审计证据和可解析的 `actualBinding`。

`actualBinding` 只能指向当前需求契约、已选结构模板或实际参数实例。验证器重新读取 `boundActual`，再依次验证：

```text
boundActual == observed
observed == expected
```

因此，“追踪文件声称宽度为 120，但实例实际为 121”会在第一关失败。图片像素不能成为工程尺寸真值；高影响假设未确认、输入冲突未解决、结构族或上下闭合选错也会阻断。

### 2.3 不可补偿

整体门禁是逻辑与，不是加权评分。任何一项失败都不能由更多线段约束、视觉相似度或较高总分抵消。第一关失败时，受控流水线不读取几何计划，不进入细节证明，也不生成 DXF/AICAD/SCR。

## 3. 第二关：逐实体和数学可靠性

### 3.1 实体协议

2D Schema 2.0 支持 `line`、`circle` 和 `arc`。每个实体包含稳定 ASCII ID、purpose、reasoning、对已生成实体的 dependencies、可验证 constraints，以及图层和生产/非生产语义。

首实体必须从 `(0,0)` 锚定。后续引用只能指向已经生成的实体；禁止零长度、非正半径、重复几何、虚假重合和前向引用。

当真实生产轮廓没有合适端点位于原点时，允许使用明确标记为非生产的 `ORIGIN_BOOTSTRAP`。验证器证明它不进入对象目录与制造输出，避免为了满足执行协议而扭曲产品。

### 3.2 独立约束秩

插件不统计“写了多少条约束”，而是计算独立约束秩。设命名顶点数为 `V`、参数变量总数为 `P`、独立设计参数数为 `K`：

```text
N = 2V + P
family_rank = N - K
instance_rank = N
instance_nullity = 0
```

结构族只允许沿声明的独立设计参数变化；具体实例必须被唯一确定。重复方程不会被误算成新增自由度消除。

### 3.3 非等式硬门禁

满秩仍可能描述错误产品，因此还要独立检查：

- 每个生产端点恰好归属一个命名顶点；
- 计划实体与几何对象一一对应；
- 外轮廓为单一、简单、闭合且不自交的环；
- 每条生产线属于命名特征、结构面或工艺区；
- 面轮廓连续、面积为正，并满足凸性或简单性要求；
- 上部和下部闭合类型分别匹配结构合同；
- 插舌、槽口、胶区、锁底片之间满足包含、间隙和顺序关系；
- 外包框、尺寸链和结构公式正确；
- 参数组合而不是仅单参数范围通过验证。

### 3.4 参数域回归

每个结构模板声明独立参数范围与跨参数不等式。验证器运行默认值、边界值、显式反例和固定随机种子的耦合参数样本，避免“每个参数单独合法、组合后互相穿透”。

## 4. 包装刀版能力

当前包装规则注册表包含 PKG-G001 至 PKG-G025，覆盖：

- 线段唯一性、端点连续和真实圆角切线；
- 开槽对称、槽宽、摇盖对口和闭合公式；
- 切割、压痕、开槽和胶区图层语义；
- 白底中文预览、对象标号与审查排版；
- 插舌主摇盖完整面、凸性和锥度方向；
- 上下闭合分别类型化；
- 需求强绑定和不可跳级输出。

默认回归结构是 ECMA A60.20.00.03：上部插舌、下部两点预粘自动锁底。它是已建模默认模板，不是所有纸盒的通用规则；其他结构必须选择相应模板并重新证明。

## 5. 交互修改器

`aicad_normality_review.py` 从已通过的正常性证明生成：

- 白色不透明 RGB PNG；
- 保留原生中文文本的 SVG；
- 可交互 HTML；
- 边、角、面对象目录；
- validation.json、validation.md、manifest 和哈希。

交互行为：

- 点击单条线，线段沿原图坐标精确高亮；
- 连续选择两条线，立即显示平行、垂直、共线、端点重合、等长、对称或联动；
- 已满足关系直接标识；
- 关系选择生成审阅草案，不会静默修改生产图；
- 可切换边号、角号和面号；
- 命中线和可见线共用同一坐标，避免点击区域与原图错位。

## 6. 第三关：受控候选输出

`aicad_guarded_delivery.py` 是包装任务的正常输出边界：

1. 运行整体需求一致性；
2. 只有第一关通过才读取几何并运行细节证明；
3. 只有第二关通过才在隔离暂存目录编译；
4. 检查所有必需工件；
5. 验证 AICAD/SCR 为 ASCII；
6. 验证 manifest 与当前源计划身份一致；
7. 为每个文件计算 SHA-256；
8. 全部通过后才原子化暴露候选目录。

已有输出目录默认拒绝覆盖，防止旧任务工件混入当前结果。暂存审计失败时，不完整候选不会被暴露。

## 7. 防乱码与审计

执行通道使用 ASCII：实体 ID、图层名、数值、受限 AICAD 指令和 AutoCAD SCR 命令。中文只进入 UTF-8 审计、验证报告和 CAD TEXT/MTEXT。

这样既保留中文用途、推理和根因，又避免区域设置、字体或命令行编码破坏 CAD 执行。

## 8. AutoCAD 适配

发布包包含 DXF、SCR、`AiCadConstraint.bundle`、AutoLISP 执行器、AICAD XData 工作流和可选 AutoCAD 2025+ 保存重开验证。

没有 AutoCAD 时，便携 2D 编译仍然可用，但 DWG、真实宿主文字、XData 持久化和保存重开必须报告为不可用，不能由 DXF 结果推断为通过。

## 9. SolidWorks 3D

3D Schema 使用逐特征交易：

```text
用途/关系 → 数学约束 → 完全定义草图 → 特征 → 重建 → 几何回读
```

当前支持：

- `base_extrude`、`boss_extrude`、`cut_extrude`；
- `center_rectangle`、`circle`、`circle_pattern`；
- 实体数、体积、表面积、边界框和故障回读；
- 持久拓扑引用；
- SLDPRT 保存、STEP 导出和重开验证；
- `--no-execute` 无宿主降级。

圆角、倒角、旋转、扫掠、放样、壳、装配体和任意曲面尚未纳入受控特征集时会明确拒绝，不会猜测或静默替代。

## 10. Agent 与 MCP

`.mcp.json` 启动本地 stdio MCP。九个工具覆盖能力查询、Schema 读取、2D 生成、验证和编译，以及 3D 宿主检查、验证和构建。

默认 Agent-first 路径不需要 API Key：

1. Agent 读取能力和 Schema；
2. Agent 根据对话与权威输入编写计划；
3. 本地插件验证和编译；
4. 插件返回结构化结果与文件路径。

`aicad_generate` 的离线 provider 只用于受控基础模板。外部模型 provider 是可选后备，不是核心运行依赖。

## 11. 错误学习闭环

每个失败报告至少包含：

- symptom：发现了什么；
- root cause：为什么发生；
- correction：当前怎样修复；
- prevention rule：下次必须新增什么规则；
- persistent rule IDs：规则编号；
- regression fixture：能稳定重现旧错误的红色测试。

这使低级错误从“一次人工提醒”变成“后续版本自动阻断”。

## 12. 验证边界

通过代表：在选定结构模板、声明参数域和已经建模的硬门禁范围内，当前实例与用户契约一致、几何被唯一确定，并且没有发现已覆盖的结构错误。

它不代表材料强度和跌落性能认证、刀模/印刷/设备公差验收、未建模结构族的正确性、自动量产许可或人工工程责任转移。

所有发布工件继续保持 `reviewOnly=true`、`accepted=false`、`ruleEnabled=false`、`packagingGated=true`。
